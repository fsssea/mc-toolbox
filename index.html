MATRIX / 三个版本

三套实现，
同一个内核。

经典版、JAVA 重制版、C++ 重制版并行维护。包名不同，所以可以同一台设备共存；共用同一套 brarchive 规范，所以谁产出的包谁都解得开。

三版都不停更不会因为新版本上线就把老版本弃掉。内核级修复（格式、规则、安全）三版同日同步发布。
三版都覆盖三端Android、Windows、Linux 都是正式发布目标，每个版本都给齐，不是“附带编译”。
同一个解析器三版都用 6.3.0 起的新 brarchive 内核，产出的容器逐字节一致，可互相打开。
解析器换代 · BREAKING

旧版 brarchive 解析器正式废弃。新内核按 brarchive-flutter（Apache-2.0）公开的容器格式规范独立重写： 对方交付的是独立 Flutter APP，而我们是“界面套壳 + 自研内核”的形态，代码不能照搬，所以只对齐格式与规则， 源码由我们用 C++ / Java / JavaScript 各写一遍，并互相做字节级交叉验证。归属声明见仓库 NOTICE.md。

NOTES / 说明

几个需要先说清楚的事。

官网只负责分发和介绍。工具箱本身不提供云同步、账号系统或在线转换服务。

转换会动我的原文件吗？

不会。打开包后先在内存里处理，只有你点保存或下载时才写出新文件。安卓版的导出结果写入应用专属目录，原包保持原样。

为什么有的内容显示“无法映射”？

基岩版与 Java 版的数据结构并非一一对应，比如部分实体组件、战利品表写法和脚本接口。转换器会把无法映射的条目列进报告，而不是悄悄删掉。

网页版能把文件存在哪？

由浏览器决定。通常下载到系统“下载”目录，或弹窗让你选择位置；网页无法直接访问安卓的 Android/data 目录。

三个版本有什么区别，要都装吗？

不用都装，按需要挑。经典版沿用网页套壳形态，体积最小；JAVA 重制版逻辑最统一，适合想要一致行为的人； C++ 重制版性能最好、功能最全，适合大批量处理。三者包名不同，真想都装也不会互相覆盖。

老版本会不会停更？

不会。三个版本并行维护，内核级修复（格式、规则、安全、校验）三版同日发布；界面级更新按各自定位推进。 任何一个版本都不会因为新版本上线被弃掉。

换了新解析器，我以前做的包还能用吗？

能读。容器格式没有变，只是修正了偏移语义与写入顺序，并补齐了旧实现的路径拼接缺陷。 但用 6.3.0 写出的包，建议用 6.3.0 及以后版本打开，避免旧解析器的已知问题。
