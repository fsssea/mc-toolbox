管理员只做一件事：给漏洞定级。

前十位通过审核的申请者拿到管理员权限。权限只有一项：把「待定」漏洞定成六种状态之一，并写清理由。两位创始人复核定级，误判超过 10 次永久取消权限。

管理员名册

名册来自仓库里的公开文件，谁在任、谁被撤销、谁记了几次误判，都写在这里，没有隐藏名单。

误判计数由创始人在驳回 Issue 里登记；申诉成立的，创始人可撤销该次记录，撤销理由必须写在同一条 Issue 里。

申请成为管理员

填 GitHub 用户名和一句申请理由，会生成一条申请 Issue；创始人按 Issue 提交顺序审核，前十位通过者入册。

提交后在 GitHub 里确认发布即可；席位按通过审核的先后顺序发放。

状态审批台

管理员在这里给「待定」漏洞定级：选六种状态之一，写一句判断依据，生成审批提案交给创始人合并。

提案不会直接改数据：创始人合并后 bugs.json 才生效，页面随之重新生成。管理员没有直接写库的权限，这是刻意的。

规则：十次误判，永久出局

下面六条是全部规则，没有口头补充。有异议就在对应 Issue 里申诉，别在评论区吵。

  • 前十位通过审核的申请者获得管理员权限；席位只发一次，被撤销后不回收、不补位。
  • 管理员权限只有一项：把「待定」漏洞定级为六种状态之一，并写明判断依据。
  • 不能下架漏洞、不能改标题、不能删别人反馈、不能封人；越权操作一律由创始人撤销。
  • 乱指挥按次计：每次定级被创始人驳回记 1 次误判；累计超过 10 次（第 11 次起）永久取消管理员权限，且不可重新申请。
  • 误判计数公开展示在名册上；申诉成立的，创始人撤销该次记录，理由写在同一条 Issue 里。
  • 两位创始人是最高管理员，不占席位，负责审核申请、复核定级、执行撤销；他们之间互相复核，不给自己记分。

创始人复核区

最高管理员用下面两条快捷入口登记误判与撤销，全部留痕在 GitHub Issue 里，公开可查。

登记后由创始人改 admins.json 的计数；满 11 次把 revoked 置为 true 并重生成页面。
